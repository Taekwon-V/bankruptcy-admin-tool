## 1. 아키텍처 및 보안 설계 (Zero-Leak Local Architecture)

### 1.1 프라이버시 및 데이터 보관 원칙
* **오프라인 100% 완전 격리**: 외부 API 서버, 클라우드 DB, 원격 텔레메트리를 일절 사용하지 않습니다.
* **디스크 구조 기반 영속성 (Portable Storage)**:
  - 모든 사건 데이터는 별도의 중앙 DB 서버 없이 로컬 파일시스템 상의 각 사건 디렉토리 내 `사건메타정보.json` 파일에 저장됩니다.
  - USB 복사나 외장하드 이동 시에도 데이터 누락이나 의존성 깨짐 없이 100% 이식 및 실행이 가능합니다.

### 1.2 네이티브 윈도우 런타임 (PyWebView 5.x)
* **프레임워크**: Python `pywebview`를 활용하여 Windows OS에 내장된 Microsoft Edge Chromium (WebView2) 런타임과 직접 통신합니다.
* **HTTP 웹서버리스 (No Localhost)**:
  - 로컬 포트 개방(`127.0.0.1:8000` 등)으로 인한 포트 충돌 및 보안 취약점을 방지하기 위해 로컬 정적 파일을 직접 로드합니다.
  - 자바스크립트와 파이썬은 `window.pywebview.api` 브릿지를 통해 직접 비동기 통신을 수행합니다.

## 2. 화면 배치 및 윈도우 지오메트리

### 2.1 좌측 50% 분할화면 자동 감지
* **구현 방식**: 윈도우 OS의 작업영역(Taskbar 제외 가용 영역) API `SystemParametersInfoW(SPI_GETWORKAREA)`를 호출하여 좌표를 계산합니다.
* **동작 파라미터**:
  - `x`: `0` (화면 맨 좌측 밀착)
  - `y`: `0` (화면 맨 상단)
  - `width`: `max(720, work_area_width // 2)` (가로 50%, 700~960px 최적화)
  - `height`: `work_area_height` (작업표시줄 바로 위까지 100% 높이)
* **목적**: 우측 50% 공간에 법원 전자소송 화면이나 한글(HWP)/PDF 서류를 동시 배치하는 실무 최적화 레이아웃.

## 4. 3x3 사건 탐색기 (Case Explorer) 세부 사양

### 4.1 디자인 시스템 & 인터페이스 (Warm Editorial)
* **컬러 팔레트**: 따뜻한 아이보리 배경 (`#fcfbf8`), 딥 포레스트 그린 상단 바 (`#1e3322`), 섬세한 베이지 테두리 (`#e8e4dc`).
* **타이포그래피**: 단일 고딕 폰트(`Pretendard`), 굵은 볼드체를 절제한 편안한 가독성.
* **상단 헤더**: 타이틀(`사건 탐색기 Case Explorer`), `+ 신규 사건 등록` 버튼, `✕ 닫기 (ESC)` 버튼.
* **상단 컨트롤러**:
  - 실시간 경로 탐색(Breadcrumb): `📁 사건저장소 › 2026년 › 08월_배정사건`
  - 슬림 검색창: 한글 초성(`ㅎㄱㄷ`) 및 사건번호/채무자명 실시간 필터링
  - 상태 필터 칩: `[전체]` + `6대 실무 상태` 원클릭 필터링

### 4.2 3단계 계층 드릴다운 및 단축 리스트
1. **Level 0 (연도 카드)**: 배정된 연도별 총 건수 및 6대 상태 요약 2열 체크리스트.
2. **Level 1 (월 카드)**: 해당 연도 내 배정 월별 건수 및 6대 상태 요약 2열 체크리스트.
3. **Level 2 (3x3 사건 카드)**: 1화면 3열 그리드 카드 레이아웃.
4. **KPI 직접 진입 (Flat List)**: 대시보드 KPI 카드 클릭 시 연도/월 폴더를 거치지 않고 해당 조건의 사건 카드들을 바로 조회.

### 4.3 6대 통일 실무 상태 (Pipeline Statuses)
* `[신규 접수]`: 파산선고 직후 관제인에게 배정된 초기 단계 (`#0284c7`)
* `[서류 보정]`: 14종 필수 서류 미비점 보정요구 및 소명 단계 (`#b45309`)
* `[통장 분석]`: 최근 1~3년 은행·보험·카드 금융거래내역 정밀 분석 단계 (`#6d28d9`)
* `[집회·보고]`: 제1회 채권자집회 기일 준비 및 법원 조사보고서 제출 단계 (`#be123c`)
* `[환가·배당]`: 은닉재산 환수, 부동산/임차보증금 환가 및 배당표 작성 단계 (`#047857`)
* `[면책·종결]`: 배당 완료 또는 이시폐지 후 면책의견 제출 및 사건 종결 (`#475569`)

### 4.4 사건 카드 세부 구성
* **헤더**: 사건번호 + 채무자명 + **44px 고정 상태 배지 (`[상담]`, `[서류]`, `[기일]`, `[보고서]`, `[종결]`)**
* **상세 정보**: 관할법원(구분), 연락처(자동 하이픈), 총 채무액(한글 독음 포맷 `1억 2,345만 원`)
* **하단 푸터**: 배정일자 + `[🚚 이동]` 폴더 이동 모달 호출 버튼

## 5. 한글 초성 & 검색 엔진 알고리즘

### 5.1 오매칭(False Positive) 방지 로직
* **초성 판별**: 입력 검색어가 한글 자음 범위(`\u3131 ~ \u314E`)로만 구성되었는지 검사 (`isPureChosung()`).
* **실행 분기**:
  - 일반 문자(예: `홍길동`) 입력 시 ➔ **텍스트 부분 일치(Substring)** 검색 수행.
  - 순수 초성(예: `ㅎㄱㄷ`) 입력 시 ➔ **초성 추출(Chosung)** 매칭 수행.
* **검색 대상 필드**: `사건번호`, `채무자명`, `전화번호`, `관할법원`

## 6. 사건 이동 및 윈도우 파일 잠금 안전 검증

### 6.1 파일 잠금(File Lock) 사전 탐지
* 사건 폴더 이동(`shutil.move`) 전 하위 모든 파일에 대해 읽기/쓰기 모드(`r+b`) 오픈 시도.
* `PermissionError` 또는 Windows WinError `32`(Sharing Violation), `5`(Access Denied) 감지 시 이동을 즉시 중단하고 안내 메시지 출력:
  > *"해당 사건의 서류(예: 통장거래내역.xlsx)가 한글/엑셀 등에서 열려 있습니다. 파일을 모두 닫은 후 다시 시도해 주세요."*
