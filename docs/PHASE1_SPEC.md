## 1. 아키텍처 및 보안 설계 (Zero-Leak Architecture)

### 1.1 프라이버시 및 데이터 보관 원칙
* **오프라인 완전 격리**: 본 프로그램은 외부 API 서버, 클라우드 DB, 원격 텔레메트리를 일절 사용하지 않습니다.
* **디스크 구조 기반 영속성 (Portable Storage)**:
  - 사건 데이터는 별도의 중앙 데이터베이스가 아닌, 파일시스템 상의 각 사건 디렉토리 내 `사건메타정보.json` 파일에 저장됩니다.
  - 이를 통해 USB 복사나 외장하드 이동 시에도 데이터 누락이나 의존성 깨짐 없이 100% 이식이 가능합니다.

### 1.2 네이티브 윈도우 런타임 (PyWebView 5.x)
* **프레임워크**: Python `pywebview`를 활용하여 Windows OS에 내장된 Microsoft Edge Chromium (WebView2) 런타임과 직접 통신합니다.
* **HTTP 웹서버리스 (No Localhost)**:
  - 로컬 포트 개방(`127.0.0.1:8000` 등)으로 인한 포트 충돌이나 보안 취약점을 방지하기 위해 로컬 정적 파일을 직접 로드합니다.
  - 자바스크립트와 파이썬은 `window.pywebview.api` 브릿지를 통해 직접 비동기 통신을 수행합니다.

## 2. 화면 배치 및 윈도우 지오메트리

### 2.1 좌측 50% 분할화면 자동 감지
* **구현 방식**: 윈도우 OS의 작업영역(Taskbar 제외 가용 영역) API `SystemParametersInfoW(SPI_GETWORKAREA)`를 호출하여 좌표를 계산합니다.
* **동작 파라미터**:
  - `x`: `0` (화면 맨 좌측 밀착)
  - `y`: `0` (화면 맨 상단)
  - `width`: `max(720, work_area_width // 2)` (가로 50%)
  - `height`: `work_area_height` (작업표시줄 바로 위까지 100% 높이)
* **목적**: 우측 50% 공간에 법원 전자소송 화면이나 한글(HWP)/PDF 서류를 동시 배치하는 실무 최적화 레이아웃.

## 3. 사건저장소 디렉토리 표준 구조

```
사건저장소/
 └── {연도}/                           # 예: 2026년
      └── {월_배정사건}/               # 예: 02월_배정사건
           └── [{사건번호}] {채무자명}/  # 예: [2026하면0201] 이지은
                ├── 사건메타정보.json
                ├── 01_기본서류/       # 인적사항, 주민초본, 과세증명 등
                ├── 02_금융내역/       # 은행/카드 계좌 거래내역 엑셀
                ├── 03_보정소명자료/   # 소명서, 시세자료, 진술서
                └── 04_보고서_산출물/  # 조사보고서(HWPX), 배당표(xlsx)
```

## 4. 3x3 사건 탐색기 (Case Explorer) 세부 사양

### 4.1 3단계 계층 드릴다운
1. **Level 0 (연도 카드)**: 배정된 연도별 총 건수 및 6대 상태 요약 2열 체크리스트.
2. **Level 1 (월 카드)**: 해당 연도 내 배정 월별 건수 및 6대 상태 요약 2열 체크리스트.
3. **Level 2 (3x3 사건 카드)**: 1화면 3열 그리드 카드 레이아웃 (스크롤 버퍼 확보).

### 4.2 6대 통일 실무 상태 (Pipeline Statuses)
* `[신규 접수]`: 파산선고 직후 관제인에게 배정된 초기 단계
* `[서류 보정]`: 14종 필수 서류 미비점 보정요구 및 소명 단계
* `[통장 분석]`: 최근 1~3년 은행·보험·카드 금융거래내역 정밀 분석 단계
* `[집회·보고]`: 제1회 채권자집회 기일 준비 및 법원 조사보고서 제출 단계
* `[환가·배당]`: 은닉재산 환수, 부동산/임차보증금 환가 및 배당표 작성 단계
* `[면책·종결]`: 배당 완료 또는 이시폐지 후 면책의견 제출 및 사건 종결

### 4.3 사건 카드 UI 구성
* **상단 헤더**: 사건번호 (18px Bold #0284c7) + 상태 뱃지 (13.5px Medium)
* **검색 경로 태그**: 검색 모드 시 `📁 2026년 · 02월 배정사건` 경로 표기
* **채무자명**: 26px Black 900
* **상세 정보 (2행)**:
  - `✔ 전화번호 : 010-0000-0000` (실시간 하이픈 포맷팅)
  - `✔ 채무액 : 1억 2,345만 2,341원` (단일 한글 독음 포맷)
* **하단 액션바**: `관할법원 (구분)` + **`[🗓️ 이동]` 버튼** (우측 하단 분리 배치)
* **인터랙션**: 마우스 오버(`:hover`) 시에만 2px 팝업 효과 적용 (초기 로딩 시 수평 기준선 유지)

## 5. 검색 엔진 알고리즘 (Chosung & Exact Search)

### 5.1 오매칭(False Positive) 방지 로직
* **초성 판별**: 입력 검색어가 한글 초성/자음 범위(`\u3131 ~ \u314E`)로만 구성되었는지 검사 (`isPureChosung()`).
* **실행 분기**:
  - 사용자가 `홍길동` 등 일반 단어를 입력한 경우 ➔ **텍스트 부분 일치(Substring)** 검색 수행.
  - 사용자가 `ㄱㅇㅊ`, `ㅎㄱㄷ` 등 초성만 입력한 경우 ➔ **초성 추출(Chosung)** 매칭 수행.
* **대상 필드**: `사건번호`, `채무자명`, `전화번호`, `관할법원`

## 6. 사건 이동 및 윈도우 파일 잠금 안전 검증

### 6.1 파일 잠금(File Lock) 탐지
* 사건 폴더 이동(`shutil.move`) 전 하위 모든 파일에 대해 읽기/쓰기 모드(`r+b`) 오픈 시도.
* `PermissionError` 또는 Windows WinError `32`(Sharing Violation), `5`(Access Denied) 감지 시 이동을 즉시 중단하고 안내 메시지 출력:
  > *"해당 사건의 서류(예: 국민은행_거래내역.xlsx)가 한글/엑셀 등에서 열려 있습니다. 파일을 모두 닫은 후 다시 시도해 주세요."*
